# Pentest Master

Операторская консоль для задач в разрешённом scope. Данные конкретных задач,
сессии, PoC и сетевые отчёты создаются локально и в исходный репозиторий не входят.

## Архитектура

- `pm.py` принимает ввод оператора и управляет жизненным циклом задачи.
- `orchestrator/` планирует работу ролей `recon`, `vuln`, `access`, `verify`,
  хранит факты и проверяет доказательства флагов и целей.
- `executor/` проверяет scope и запускает сетевые инструменты через NetGuard.
- `mcp/server.py` предоставляет инструменты агентам; `integrations/burp-bridge/`
  импортирует метаданные Burp. `runtime/` содержит точки входа и профили.
- `storage/`, сессии и журналы — локальные рабочие данные; они исключены из git.

## Установка

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python pm.py --help
```

## Evidence Hub

Evidence Hub связывает завершённые сетевые исследования и метаданные Burp
Proxy History в доказательный пакет для четырёх ролей. Для существующей задачи
задайте её номер в переменной `TASK_ID`:

```bash
TASK_ID=1  # замените на номер своей задачи
# 1. Сверка двух источников без токенов и без сетевой активности
.venv/bin/python orchestrator/evidence_pipeline.py status --task-id "$TASK_ID"

# 2. Четыре анализа модели по объединённым наблюдениям
.venv/bin/python orchestrator/evidence_pipeline.py agents --task-id "$TASK_ID"

# 3. Повторно: никаких API-вызовов, если данные не изменились
.venv/bin/python orchestrator/evidence_pipeline.py resume --task-id "$TASK_ID"
```

Когда Burp открыт и появились новые HTTP-запросы:

```bash
# Импорт и обновление пакета доказательств без LLM
.venv/bin/python orchestrator/evidence_pipeline.py sync --task-id "$TASK_ID"

# Анализ новой версии пакета (ключ API потребуется снова)
.venv/bin/python orchestrator/evidence_pipeline.py agents --task-id "$TASK_ID"
```

Для полного действия одной командой при **запущенном Burp**:

```bash
.venv/bin/python orchestrator/evidence_pipeline.py run --task-id "$TASK_ID"
```

В `run` сначала синхронизируется Burp History, затем при необходимости выполняются 4 вызова модели. В режиме `agents` сеть не сканируется и Burp не требуется.

## Новые таблицы SQLite

- `evidence_snapshots`: слепки набора наблюдений с SHA-256.
- `evidence_agent_reports`: 4 отчёта на **версию** слепка, без удаления старых отчётов.

Хеш не меняется при повторных запусках без новых наблюдений. При появлении нового Burp наблюдения слепок меняется; старые отчёты сохраняются, а новые агенты могут сформировать новые версии отчётов.

## MCP сервер

`integrations/evidence_hub_mcp.py` — отдельный `stdio` MCP сервер с инструментами:

- `evidence_status(task_id)` — получить структурированные подтверждённые сетевые наблюдения и метаданные Burp;
- `evidence_sync_burp(task_id,limit)` — подтянуть метаданные из локального Burp без запросов к тестируемым целям.

Сервер **не регистрируется автоматически** в текущем Harness/MCP. Для использования этих MCP-инструментов требуется добавить сервер в конфигурацию Harness или явно подключить в основном MCP. CLI `evidence_pipeline.py` уже работает напрямую, без этого шага.

## Консоль `pm.py`: доступность, флаги и подсказки

Перед запуском агентов консоль перепроверяет TCP-порты из полного скана через
NetGuard задачи. Если все порты недоступны, запуск останавливается; явный
`--force-unreachable` у `new`/`resume` разрешает продолжить после этой проверки.
Кэш полного скана старше 30 минут сопровождается предупреждением.
Порог можно задать через `PM_TCP_SCAN_STALE_MINUTES`.

Поиск флагов текстовый. По умолчанию ищутся `PREFIX{...}` с существующими
ограничениями алфавита и значения после ключей `flag`, `flags`, `token`,
`secret`, `answer` (`:` или `=`). Флаги без фигурных скобок, с другим
алфавитом или длиной требуют `--flag-pattern REGEX`, `--flag-prefix THM,HTB`,
`--flag-shape uuid,hex32` или точного значения `--flag-expect VALUE` /
`--flag-expect-file PATH`. Формы `uuid`, `uuid_nohyphen`, `hex32`, `hex40`,
`b64`, `digits` выключены по умолчанию из-за частых ложных совпадений.
Опции принимают команды `new`, `attack`, `resume`, `intent`; шаблоны задачи
видны в поле `patterns_used` отчёта цикла. Подтверждение требует двух
независимых сетевых источников либо явного подтверждения оператора. Локальные
совпадения PoC остаются кандидатами с `local_only`.

`--hints-file PATH` у `new` и `intent` читает подсказки UTF-8 с переносами
строк. Лимит описания вместе с подсказками — 6000 символов, подсказок — 6000
символов. Считаются символы, не байты; ошибка дополнительно показывает размер
UTF-8 в байтах. При чтении старого слишком длинного описания агент получает
маркер числа обрезанных символов.

Причины остановки ролевого цикла: `iterations_done`, `flag_confirmed`,
`no_progress`, `stalled`, `state_unavailable`, `recon_failed`, `vuln_failed`,
`target_unreachable` (две итерации без новых наблюдений, все сетевые вызовы
завершились тайм-аутом или недоступностью), `goal_confirmed`,
`objectives_done`, `flags_without_goal`.

Основная цель — текст ответа на вопрос «Что требуется сделать». Побочные
флаги-цели вводятся отдельным вопросом либо через повторяемый
`--objective "400:описание"` / `--objectives-file PATH` (одна позиция на
строку, `#` — комментарий). Вес от 1 до 10000; для основной цели действует
`--goal-weight N` (по умолчанию 100). В консоли побочные позиции разделяются
`;`, а `\;` означает буквальную точку с запятой в описании.

Режим `--goal-first` (по умолчанию при заданных целях) сначала проверяет
основную цель, затем побочные до ожидаемого числа флагов. `--goal-exclusive`
останавливает цикл сразу после доказательства основной цели. `--all-flags`
сохраняет прежний поиск до `--expect-flags N`. Без явного `--expect-flags` у
задачи с целями ожидается один основной флаг плюс число побочных позиций.
Цель подтверждается только флагом с двумя независимыми сетевыми источниками
и существующим `result_id` зонда, который агент привязал к цели. Заявление
агента само по себе доказательством не считается. Подсказки помогают агентам,
но не влияют на счёт целей и условие остановки.

## Ограничения

- Сохраняются метаданные Burp: метод, порт, схема, статус, хеш пути; не читаются тела, cookies, Authorization или query string.
- Проверки Task Scope сохраняются в исходных Network Workflow и Burp importer.
- `evidence_pipeline.py` **не выполняет активных сетевых проверок**. Его Harness-подсказка запрещает вызовы инструментов, но запрет по подсказке — не механизм безопасности: пока SDK конфигурация предоставляет MCP-инструменты, блокирование `tool/call` здесь срабатывает **после** события. Для production необходимо ограничить доступные инструменты на уровне конфигурации/исполнителя.
- Подтверждение HTTP ответа или открытого порта не равно подтверждению уязвимости.
- Для каждого запуска анализируется до 60 сетевых наблюдений и 50 последних Burp-записей; это ограничение размера контекста, а не полный исторический отчёт.
