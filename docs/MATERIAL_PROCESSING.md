# Обработка сохранённых материалов по фактическому типу

Реализовано от `264a725`, без обновления SDK/установленных системных пакетов.
Код: [material_processing.py](../orchestrator/material_processing.py),
[material_worker.py](../orchestrator/material_worker.py), публичные инструменты
в [MCP server](../mcp/server.py). Это локальные преобразования, а не сканирование,
исполнение полученного кода или новый реестр подтверждённых фактов.

## Вход и выбор обработки

`pm_material_import(task_id,path)` принимает **относительный** путь обычного файла
в пространстве текущей задачи `/var/lib/pentest-master/work/<task_id>/`.
Снимок сохраняется приватно и возвращает `file_material:ID`. Переходы `..`,
symlink и чужой владелец отвергаются. Изменение файла в workspace не меняет
сохранённый снимок. Каталог можно передать как архив; директории произвольной
Kali, целевые shell-команды и clone этим инструментом не открываются.

`pm_material_process(task_id,reference,operation="auto",options_json="{}")`
принимает проверенную ссылку общей памяти, в том числе HTTP-artifact, прежний
результат/отчёт, файл или результат преобразования. Тело HTTP-capture остаётся
байтами, а не строковым repr/base64, ошибочно принятым за файл.
Данные всегда привязаны к задаче; изменённый хэш/чужая ссылка отвергаются.
`file` и структурные magic bytes определяют тип; расширение не решает выбор.
Несовместимый явно заданный обработчик возвращает ошибку.

| Тип | Реальная обработка | Границы |
|---|---|---|
| Текст | UTF-8/BOM UTF-16/32; явная Python-кодировка, например cp1251 | нет молчаливой замены повреждённых символов; неоднозначность требует encoding |
| Архив | Python ZIP/TAR, gzip; каждый обычный member сохраняется отдельно | пути/links/devices не исполняются и не следуются; другие форматы пока unsupported |
| PDF | установленный Poppler `pdftotext` | PDF без текста или `ocr=true` требует OCR; исходный PDF сохраняется |
| Изображение/OCR | Tesseract CLI с установленными языковыми данными | это транскрипция с возможными ошибками, не точная цитата байтов оригинала |
| Исполняемый файл | ELF metadata через `readelf`, static `objdump -d`, `strings` | файл не запускается; строки не доказывают поведение, доступ или эксплуатацию |
| Git | установленный Git: index-pack/verify-pack/cat-file/ls-tree, локально | loose SHA-1, pack/index и delta; нет fetch/checkout/hooks/filters |

**Hydra** предназначена для сетевой аутентификации, **Ghidra** — для обратного
анализа/декомпиляции. Они не взаимозаменяемы. Здесь работает статический binutils,
а не пустой «адаптер Ghidra». Ghidra в текущем окружении не установлен; автоматический
headless-декомпилятор и универсальная поддержка архитектур не заявлены.
Модель выбирает обработку и интерпретирует сохранённые результаты через прежний
Harness; она не получает право угадывать бинарное содержимое или запускать файл.

Профиль [material-analysis](../instructions/procedures/material-analysis.md)
доступен всем четырём ролям. Он не разрешает сеть/PoC/PTY. Saved-analysis также
получает локальные обработчики, поэтому выключенная машина не мешает анализу.
Исходное задание, ограничения, конкретный вопрос и expected_result сохраняются
в полном и сжатом промптах. Нерелевантные процедуры не подключаются.

## Git, связанные файлы и происхождение

Репозиторий можно передать сохранённым архивом с `.git/objects/...` либо набором
исходных refs. При обнаружении Git-объектов внутри архива выполняется Git-аудит.
Для отдельного pack/index поддержана явная связь, например:

```json
{"related":[{"reference":"file_material:42","path":"objects/pack/source.idx"}]}
```

Если основной вход — index, нужен соответствующий pack и `operation="git"`.
Для loose допускается `object_id` из исходного URL/метаданных. Проверяются
заголовок/длина и SHA-1 object header+content. Git проверяет CRC/pack/index/delta;
каждый возвращённый объект дополнительно сверяется по типу, длине и SHA-1.
Повреждённый index, hash mismatch и thin pack без основы — явные ошибки.
SHA-256-репозитории и автоматическое получение отсутствующих объектов пока
не реализованы; отсутствие объекта не заполняется выводом модели.
`object_id` также выбирает конкретный объект из pack/репозитория по полному
индексу, в том числе вне первой выборки 256. Сохраняются requested_object,
objects_selected/omitted и all_objects_transformed. Завершение такого запроса
не означает анализа всех объектов репозитория; другой полезный объект доступен
следующим локальным вызовом без сети и операторского gate.

В новый временный bare repo копируются только inert object/pack/index bytes.
Исходные config/hooks/alternates/grafts/promisor/replace refs не применяются.
Штатный Git запускается без global/system config, с protocol.allow=never,
без lazy fetch, replacement objects и пользовательских templates.
Рабочее дерево не checkout-ится, Git symlinks остаются данными tree.

Сохраняются object IDs, tree paths/modes, submodule gitlinks и точные URL из
config/.gitmodules/.lfsconfig; LFS pointers сохраняют SHA256 и размер.
Это **метаданные связанных материалов** с fetched=false/authorized=false,
не разрешение исследовать сторонний узел. Загрузка возможна только отдельным
действием через прежние scope/HTTP/вопросы оператору. Дополнительный полезный
файл того же репозитория не вызывает повторного disclosure checkpoint.

## Оригиналы, полнота, память и отсутствие инструмента

Добавочные таблицы в прежней SQLite: `pm_file_materials` и
`pm_material_processing`. Данные — `artifacts/materials/<task_id>/<sha256>`;
каталог 0700, файлы 0600, проверка размера/хэша при чтении. Исходные bytes
фиксируются до запуска обработчика. Производные сохраняют parent/source refs,
параметры, processor_version, использованные executable paths/exit codes и ошибки.
Повторная инициализация сохраняет строки; старые task/report/capture не мигрируют
и не переписываются. Публикация производных/receipt выполняется через savepoint.
Неудача преобразования/квоты не удаляет оригинал. Уже завершённые outputs имеют
checkpoint для сохранения после аварийного завершения worker.

`complete`/`source_complete`/`transformation_complete` различаются: известная
неполнота исходника не превращается в полноценный материал после декодирования.
Неизвестная полнота исходного результата явно null. Полная конверсия текста
не является утверждением, что модель уже проанализировала весь файл.
Чтение/охват работает через прежний `pm_material_read` и material_analysis.

Лимиты: файл ≤64 MiB, content-addressed файлы задачи ≤256 MiB, derived output
≤64 MiB и ≤512 файлов, Git — до 256 выбранных объектов с сохранением полного
object index/числа пропущенных. OCR PDF — явное окно 1–8 страниц; whole-document
OCR не объявляется выполненным. Текстовый слой PDF обрабатывается отдельно.
Превышение/пропуски отмечаются; исходник не обрезается ради размера промпта.
Разбор member/следующего объекта выполняется отдельным поручением по сохранённой
ссылке. Недостаток квоты требует явного решения, не скрытого увеличения лимита.

Структурные признаки ключей/credential URI/Authorization и использование
произвольно названной переменной в аутентификации дают **кандидатов**, не доступ.
Их значения и source refs приватно доступны памяти. Детектор ограничен и не
обещает найти любой секрет; интерпретация кода/использования остаётся за моделью.
Пароль/токен не становится флагом без связи с целью. Кандидат флага любого
формата передаётся в существующую операторскую очередь из ролевого отчёта;
принятие платформой возможно без capture/нового GET/VERIFY/живой машины.

Для локального VERIFY/цитирования ролевой отчёт указывает **оригинальный**
material_process/import result_id и `artifact_ref=file_material:ID`, точную
UTF-8 цитату. Валидатор сверяет task, typed capability receipt, сохранённый
processing record, хэши файлов и цепочку оригиналов. Новый GET не нужен.
Проверенная ссылка получает evidence_reused/local_audit и не публикуется как
новое наблюдение или доступ. Повреждение, чужая ссылка и произвольный stdout
PoC этим путём не принимаются. Прежний HTTP/loose capture аудит сохранён.

При отсутствии поддержанного анализатора `pm_material_process` возвращает
tool_missing и через `pm_tool_request` создаёт прежнюю APT-квитанцию/вопрос.
Повтор не дублирует разрешение. Установки без ответа нет; отказ сохраняется
для выбора другого метода. Поддержанные package names перечислены в
[TOOLS.md](TOOLS.md). Установленный root broker при разработке не обновлялся;
старый broker может явно отказать новому имени пакета. Это не успешная установка.
Иные пакеты/языки не разрешаются произвольным root argv.

Worker имеет отдельную process group, CPU/address-space/file-size лимиты,
дедлайн native операции 20 сек и общий 90 сек. Завершение/отмена убирает дочернюю
группу. Seccomp запрещает новые socket/connect/send syscalls до разбора; проверка
воспроизводит EPERM. Это **не полная filesystem sandbox против уязвимости native
parser**: процесс имеет обычные пользовательские права. Полученные исполняемые
файлы не исполняются и не получают дополнительные системные/сетевые разрешения.

## Фактически проверено

[test_material_processing.py](../tests/test_material_processing.py):

- Реальные UTF-16/CP1251 и несовместимая кодировка, поддельное расширение.
- ZIP с допустимым member/traversal, TAR репозитория; оригиналы и ошибки сохранены.
- Настоящий Poppler читает созданный PDF; повреждённый PDF сохраняет stderr/ошибку.
- Настоящие binutils разбирают `/usr/bin/true` без исполнения образца.
- Git создаёт репозиторий с историей и **реально проверенными delta-объектами**,
  проверяются pack+index и index+pack, loose/hash mismatch, повреждённый index,
  LFS/URL/gitlink metadata без загрузки.
- Настоящий FastMCP dispatch → импорт/worker/SQLite → memory/read → полный и
  сжатый prompt. Нет подмены файловых анализаторов этими fake результатами.
- Настоящие run_role и координатор с подменённой моделью принимают локальную
  файловую цитату с производственно вычисленным prior_ids, без сетевого зонда
  и report_incomplete; повреждение оригинала отвергается, новый факт не создаётся.
- Чужая задача, tampering, повторная инициализация, неполный источник, ошибка
  публикации, cached readback и fingerprint нового полезного файла.
- Неизвестный формат флага из PDF проходит прежнюю очередь ответа оператора;
  при выключенной машине выполненная цель завершается до следующей модели.

**OCR-транскрипция здесь не испытана:** tesseract CLI и traineddata недоступны.
Создано настоящее PNG, проверены корректная классификация и tool_missing;
в отдельном контракте ограничена видимость executable PATH реального worker,
подменён только broker prepare — настоящий сохраняемый вопрос, без установки.
Это не заглушка распознавания и не положительный OCR-runtime. Тест имеет
положительную ветку для установленного eng, но в этом прогоне она не выполнялась.
Ghidra headless, живые цели/GLM и настоящая привилегированная APT-установка не
запускались. Рабочая SQLite/отчёты/доказательства этим этапом не изменялись.


## Выбор результата OCR, исправление от `40789e6`

Тест выбирает материал по `metadata.kind=ocr` и описанию OCR-транскрипции,
проверяет полноту и распознанные байты. `outputs[0]` может быть analyzer_stderr
с оценкой разрешения Tesseract; порядок не определяет тип результата.
Диагностика сохраняется отдельным материалом без подавления stderr.
Отдельная regression-фикстура воспроизводит diagnostic-first порядок: это
контракт выбора результата и настоящее файловое хранилище, **не OCR runtime**.

В текущем окружении tesseract CLI отсутствует. Настоящее распознавание и eng
не испытаны; положительная ветка теста выполняется только при их наличии.
Проверены реальное PNG/type, tool_missing и прежний сценарий сохраняемого
вопроса оператору с отсутствующим инструментом; установка не выполнялась.
