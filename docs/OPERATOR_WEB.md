# Браузерный просмотр. Этап 1

```bash
pentest-master web
pentest-master web --port 8766
```

Откройте URL из терминала в браузере Kali. PM слушает только IPv4 loopback.
Введите Ctrl+C в терминале, чтобы прекратить просмотр. Параметр
`--storage PATH` у `web` и `status` открывает сохранённую копию из каталога
PATH. В нём ожидаются `tasks.db`, `run_events/` и `method_library/catalog.json`.
По умолчанию берётся рабочее `storage/`. Для советов действует существующая
переменная `PM_METHOD_LIBRARY_DIR`, если не задан `--storage`.

| Поле | Источник |
|---|---|
| Список, адрес, дата и записанный статус задачи | `tasks` |
| Задание и ограничения оператора | `pm_task_intents.intent`; описание `tasks.description` у старых задач подписано отдельно |
| Допуск, область, исключения и закрытие | `pm_operator_approvals`, `pm_resource_scope`, `task_scope_settings`; также учитывается явный `tasks.status=closed` |
| Доступность цели | Сохранённая запись `pm_target_availability` |
| Последний вызов PM | Связанные с задачей `run.start`, `run.end`, `run.summary` из `run_events/*.jsonl`. Повреждённые строки отмечаются по ID запуска, если его связь с задачей установлена |
| Режим, состояние координатора, роли и шаги | `pm_task_runtime`, `pm_coordinator_runs`, `pm_coordinator_steps`; исторические `master_auto_runs`, `agent_runs` и `tasks.plan_json` показаны отдельно |
| Вопросы | Сохранённая очередь из `operator_questions.listing` без reconcile. Браузер показывает ожидающие вопросы, CLI также показывает историю |
| Итог цели и прогресс | `pm_flag_review_policy`, `pm_flag_proposals`, `pm_objectives`, для прежней политики `pm_verified_flags` |
| Отчёты | Ссылки на выбранные поля канонических `pm_agent_action_reports`, `evidence_agent_reports`, `lab_agent_reports` |
| Советы | `method_library.Library.read()` читает текущий приватный каталог и все сохранённые версии |

Состояние вызова PM, ожидание оператора, итог цели и закрытие отображаются
раздельно. При наличии ручной политики браузер, `status` и приглашение очистки
используют сохранённые подтверждения и обязательные цели. Принятый флаг при
единственной выполненной цели с ожиданием одного флага даёт «Цель достигнута ·
1 из 1». Очистка требует отдельного ответа оператора в CLI. Для прежней политики
сохранён критерий двух подтверждённых значений с двумя свидетельствами на каждое.
Если сведений недостаточно, итог цели неизвестен.

Каждая страница читает SQLite через `mode=ro` и `query_only`. Штатная БД PM
работает в режиме DELETE. Каждый запрос заново читает сохранённое состояние,
поэтому обновление страницы после commit показывает новые данные даже при
открытом пишущем соединении. WAL-база возвращает явную ошибку. SQLite может
создать WAL и SHM при открытии исходника с `mode=ro`. Для просмотра можно
передать отдельную согласованную копию в режиме DELETE через `--storage`.
Эта копия показывает состояние на момент копирования.

`questions ID`, `questions ID --json` и выход из пункта «Вопросы» через Enter
читают очередь без миграций, активации политики, reconcile и диагностического
запуска. Явные ответы и другие действия оператора по-прежнему записываются.
`status` и пункт «Отчёт» показывают порты текущего адреса из сохранённого
полного TCP-скана и доступные сведения о сервисах и HTTP из последнего снимка.
`status --json` сохраняет прежние поля Evidence Hub. Отсутствующая информация
представлена `null`.

У страницы отчёта фиксированный адрес внутри PM и выбранные поля из SQLite.
Перед HTML-экранированием браузер маскирует распознаваемые заголовки с
учётными данными и именованные секреты по правилам диагностики PM.
Исходные поля сохраняются в хранилище.
Просмотр не открывает произвольные пути, сохранённые в отчётах. В браузер
выдаются только поля карточки совета и история версий. Архивы, оригиналы,
хэши происхождения и сырой каталог остаются в хранилище. Ошибка чтения совета
показывается на странице советов. Задачи доступны независимо от каталога.

Проверка запускается через проектный launcher, установленный во временном
пользовательском каталоге. Она использует временные БД, журналы и каталог под
storage guard, локальный HTTP и Chromium. Тесты сверяют исходные файлы и схему
после чтения и проверяют маскирование как в HTTP-ответе, так и в DOM.

```bash
.venv/bin/python tests/run_offline.py --runtime --only test_operator_web_runtime
.venv/bin/python tests/run_offline.py
git diff --check
```
