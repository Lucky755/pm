# Браузерный интерфейс PM. Этапы 1–3

```bash
pentest-master web
pentest-master web --port 8766
```

Откройте URL из терминала в браузере Kali. PM слушает только IPv4 loopback.
Введите Ctrl+C в терминале, чтобы остановить локальный сервис. Параметр
`--storage PATH` у `web` и `status` выбирает каталог данных. В нём ожидаются
`tasks.db`, `run_events/` и `method_library/catalog.json`. Явные записи из web
при таком запуске относятся к выбранному каталогу.
По умолчанию берётся рабочее `storage/`. Для советов действует существующая
переменная `PM_METHOD_LIBRARY_DIR`, если не задан `--storage`.

| Поле | Источник |
|---|---|
| Список, адрес, дата и записанный статус задачи | `tasks` |
| Задание и ограничения оператора | Исходный сохранённый текст и последующие редакции из `pm_task_intents` и `pm_task_intent_history`. Описание планировщика из `tasks.description` показывается отдельно |
| Допуск, область, исключения и закрытие | `pm_operator_approvals`, `pm_resource_scope`, `task_scope_settings`; также учитывается явный `tasks.status=closed` |
| Доступность цели | Сохранённая запись `pm_target_availability` |
| Последний вызов PM | Связанные с задачей `run.start`, `run.end`, `run.summary` из `run_events/*.jsonl`. Повреждённые строки отмечаются по ID запуска, если его связь с задачей установлена |
| Режим, состояние координатора, роли и шаги | `pm_task_runtime`, `pm_coordinator_runs`, `pm_coordinator_steps`; исторические `master_auto_runs`, `agent_runs` и `tasks.plan_json` показаны отдельно |
| Вопросы | Сохранённая очередь из `operator_questions.listing` без reconcile. Схема показывает ожидающие вопросы, раздел «Управление» и CLI также показывают сохранённые ответы |
| Итог цели и прогресс | `pm_flag_review_policy`, `pm_flag_proposals`, `pm_objectives`, для прежней политики `pm_verified_flags` |
| Отчёты | Ссылки на выбранные поля канонических `pm_agent_action_reports`, `evidence_agent_reports`, `lab_agent_reports` |
| Советы | `method_library.Library.read()` читает текущий приватный каталог и все сохранённые версии |

Состояние вызова PM, ожидание оператора, итог цели и закрытие отображаются
раздельно. При наличии ручной политики браузер, `status` и приглашение очистки
используют сохранённые подтверждения и обязательные цели. Принятый флаг при
единственной выполненной цели с ожиданием одного флага даёт «Цель достигнута ·
1 из 1». Очистка требует отдельного ответа оператора в CLI. Для прежней политики
сохранён критерий двух подтверждённых значений с двумя свидетельствами на каждое.
Если сведений недостаточно, итог цели неизвестен.

Запросы просмотра читают SQLite через `mode=ro` и `query_only`. Штатная БД PM
работает в режиме DELETE. Каждый запрос заново читает сохранённое состояние,
поэтому обновление страницы после commit показывает новые данные даже при
открытом пишущем соединении. WAL-база возвращает явную ошибку. SQLite может
создать WAL и SHM при открытии исходника с `mode=ro`. Для просмотра можно
передать отдельную согласованную копию в режиме DELETE через `--storage`.
Эта копия показывает состояние на момент копирования.

`questions ID`, `questions ID --json` и выход из пункта «Вопросы» через Enter
читают очередь без миграций, активации политики, reconcile и диагностического
запуска. Явные ответы и другие действия оператора по-прежнему записываются.
`status` и пункт «Отчёт» показывают порты текущего адреса из сохранённого
полного TCP-скана и доступные сведения о сервисах и HTTP из последнего снимка.
Закрытые и неопределённые порты из снимка не попадают в список открытых.
`status --json` сохраняет прежние поля Evidence Hub и показывает открытые порты
отдельно в `findings.tcp` и `findings.udp`. Отсутствующая информация представлена
`null`.

У страницы отчёта фиксированный адрес внутри PM и выбранные поля из SQLite.
Перед HTML-экранированием PM маскирует распознаваемые заголовки с учётными
данными, включая `X-API-Key` и `Proxy-Authorization`, и именованные секреты
по правилам диагностики.
Исходные поля сохраняются в хранилище.
Просмотр не открывает произвольные пути, сохранённые в отчётах. В браузер
выдаются только поля карточки совета и история версий. Архивы, оригиналы,
хэши происхождения и сырой каталог остаются в хранилище. Ошибка чтения совета
показывается на странице советов. Задачи доступны независимо от каталога.

## Схемы, маршрут и история

- **Агенты.** Карточки опираются на сохранённые шаги координатора. Стрелка
  появляется, когда `coordinator.decision` связывает конкретный шаг с конкретным
  запуском координатора. У шага без этого события источник назначения неизвестен.
- **Карта цели.** Открытые порты берутся из структурированного инвентаря,
  завершённого TCP-скана и сохранённого снимка. Веб-приложения берутся из области,
  снимка и метаданных сохранённых HTTP-ответов. Для HTTP-приложения показываются
  сохранённые схема, хост, порт и путь. При неполной записи используются
  доступные части. IPv6-адрес отделяется от порта квадратными скобками.
  Данные авторизации скрываются, значения query маскируются.
  Сессия связывается с целью по
  записанному ресурсу. Следующее ребро опирается на `pm_pivot_routes` и указывает
  сохранённую сессию и ресурс. Подтверждённый маршрут имеет состояние `active`
  и проверяемую сохранённую квитанцию. Карта показывает последнее сохранённое
  состояние и не проверяет соединения заново. В узком окне схему можно
  прокручивать по горизонтали.
- **История.** Хронология объединяет записи `run_events`, журнал возможностей MCP
  этой задачи, сохранённые HTTP-обмены и ответы из очереди SQLite. Технические идентификаторы доступны в
  деталях. Для команд выводятся сохраняемые части массива аргументов. Секреты,
  непрозрачные аргументы, тела и значения query скрываются. Если журнал сохранил
  только тип операции, это указано в деталях. Старая запись без журнала
  назначения или без сохранённых аргументов остаётся неполной. Отдельные записи
  разных источников могут описывать одно действие, например запись результата
  MCP и его диагностическое завершение. Нечитаемые строки известного запуска
  отмечаются, корректные записи остаются доступными.
  У HTTP-обмена ID сессии показан отдельным полем с маскированием.
  Исполнитель берётся из квитанции MCP с явно указанным ID этого обмена
  и сохранённой ролью. Без однозначной связи интерфейс показывает
  «Исполнитель не записан».

Браузер периодически читает одну проекцию задачи по `GET /tasks/ID/view.json`.
Карточки, связи, вопросы и строки истории обновляются по сохранённым ключам.
Повторное чтение идентичного события не создаёт вторую строку. При временной
ошибке чтения остаётся последнее показанное состояние. Проекция считывается
целиком и не хранит курсор на сервере.

## Управление задачами

- **Новый контекст.** Пройдите «Контекст → Цели → Проверка» и нажмите
  «Сохранить контекст». Черновик остаётся в `pm_context_drafts` и открывается
  из «Управления». Его текст можно использовать при отдельной работе в CLI.
  Проверка адреса и имён выполняется без DNS. Порт и путь URL остаются в исходном
  значении. Пустое поле формата означает, что формат неизвестен. До сохранения
  шаги мастера не пишут в хранилище.
- **Уточнить контекст.** Сначала проверьте номер задачи. Уточнение и имена по
  сообщению оператора добавляются в существующую историю `pm_task_intent_history`.
  Карточка задачи и форма показывают описание планировщика, исходное задание
  и уточнения раздельно. Если исходного задания в истории или сохранённом
  контексте нет, оно отмечено как неизвестное. Уточнения прежнего PM Web
  распознаются по источнику записи и сохранённому изменению текста.
  Отдельный блок показывает имена, для которых PM сохранил подтверждённую
  привязку. Запись уточнения использует версию открытого текста задания.
- **Вопросы.** Для информационного вопроса сохраните текстовый ответ. Старый
  вопрос об инструменте без квитанции разрешения также принимает только текст.
  Запросы с разрешениями, бюджеты и шаги ACCESS показывают сохранённый статус.
  Решение по флагу связано с конкретным кандидатом и его версией. Проверьте
  показанное значение на CTF-платформе самостоятельно и затем примите или
  отклоните его. Для отклонённого кандидата доступен явный пересмотр с причиной.
  Если другая вкладка уже ответила, web показывает сохранённое решение.
- **Итоговый отчёт.** Показывает результат по общему правилу CLI, подтверждённые
  цели, статусы кандидатов, открытые вопросы и закрытие задачи. Принятие
  последнего флага не запускает очистку или следующую операцию.
- **Библиотека советов.** При сохранении и исправлении укажите задачу, Result ID,
  ссылку на оригинал и безопасную точную цитату. PM сверяет оригинал локально.
  Поддержанные основания и поля описаны в [формате библиотеки](METHOD_LIBRARY.md).
  Перед записью есть экран проверки. Для исправления или отзыва нужны версия и
  причина. При конфликте перечитайте карточку. Отмена оставляет каталог прежним.
  Для `web --storage PATH` оригиналы берутся из `PATH/artifacts/http` и
  `PATH/artifacts/materials`, квитанции — из `PATH/capability_log`.

Запуск и возобновление операций, применение сетевых привязок, выдача
разрешений на действия и очистка среды остаются в CLI. Web использует
проверенный loopback Origin, отдельный CSRF-токен для формы и POST для
изменений. После успешной записи открывается читающий адрес без содержимого
формы в URL. Сервис рассчитан на доверенного пользователя локальной машины.

Проверка запускается через проектный launcher, установленный во временном
пользовательском каталоге. Она использует временные БД, журналы и каталог под
storage guard, локальный HTTP и Chromium. Тесты сверяют исходные файлы и схему
после чтения и проверяют маскирование как в HTTP-ответе, так и в DOM.

```bash
.venv/bin/python tests/run_offline.py --runtime --only test_operator_web_runtime
.venv/bin/python tests/run_offline.py
git diff --check
```

Чтобы сохранить три снимка наполненной фикстуры, передайте каталог через
`PM_WEB_SCREENSHOTS`.

```bash
env PM_WEB_SCREENSHOTS=/tmp/pm-web-stage2-screenshots .venv/bin/python tests/run_offline.py --runtime --only test_operator_web_runtime --verbose
```

Тот же запуск сохраняет снимки мастера, информационного вопроса и итога
принятия флага. Набор также проверяет отказ внешнего Origin, неправильного
CSRF и чужого кандидата по сырому HTTP отдельно от Chromium.
